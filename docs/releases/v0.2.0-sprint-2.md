## Sprint 2 retro

### What worked well

- **STOP-ASK gates fired at material moments.** Day 19 §20 list mismatch surfaced before bad data landed in the seed script. Day 14 audit_logs scope decision halted what would have been "log everything everywhere" sprawl. Day 11 root-credentials prep saved the staging deploy from immediate 500s. The STOP-ASK habit became a sprint pattern, not just a brief artefact.
- **Per-domain audit helpers + append-only invariant + render-at-publish-sanitization became reusable patterns.** Day 14 introduced `services/audit/kyc.ts` with `writeKycTransition()`; Days 15-19 added 5 more helpers across 3 domain files (`kyc.ts`, `tenant.ts`, `legal.ts`) following the same shape. Append-only invariant from Day 14 (`audit_logs`) replayed cleanly to Day 19 (`legal_document_versions`) with the same `REVOKE UPDATE, DELETE, TRUNCATE` boilerplate. Render-at-publish (Day 19 Decision J) pattern is the model for any future markdown-or-similar sanitization surface.
- **`/review` caught material BLOCKERs in PR.** Day 18 PR 3 (backend KYC review queue): 3 IMPORTANTs fixed in-PR. Day 18 PR 4 (frontend KYC review queue): 2 BLOCKERs + 3 IMPORTANTs fixed in-PR. Day 17 PR 1 (Org Tier A backend): 1 BLOCKER (BIN regex accepting deprecated formats) + 2 IMPORTANTs in-PR. The cumulative `/review` save per sprint approached "one extra full day of bug-fixing work avoided" — net positive even at the time-cost of running it.
- **Memory protocol kept context across 10 working days.** Each day's session started by reading `handoff.md` + the last 5 `decisions.md` entries + `progress.md` In-flight. Sprint 2 spanned 49 commits and 16 Items; no Item shipped without a memory-backed handoff between sessions. Days 18-19 (largest single days of the sprint) only worked because Days 11-17 had been faithfully captured.

### What didn't work

- **OAuth bug silently sat for 9 working days.** Sprint 1 Day 7-8 scaffolded sign-in button hrefs as placeholders (`/api/auth/{provider}/start`). Real routes landed (`/api/v1/auth/oauth/{provider}/start`) but buttons never got updated. Manual happy-path verification was a deferred carry that nobody pulled forward. Caught Day 20 only because it surfaced in the AM brief explicitly. Pattern: "frontend ships ahead of backend → wire-up step gets deferred → 9 days of broken silent." Sprint 3 must front-load wire-up verification when frontend lands ahead of backend.
- **Multiple per-item deferrals accumulated before Day 18 consolidation.** Porichoy deferred 2026-05-17, Item 10 deferred 2026-05-17, Day 17 BIN regex BLOCKER surfaced 2026-05-19 — three separate deferral entries within 48 hours all pointed to the same underlying truth (third-party verification doesn't work for MVP). Day 18 AM consolidated into the platform-wide policy. Could have been one entry at Sprint 2 kick-off if the deferral pattern had been recognised earlier. Net cost: ~3-4 hours across the three Day 17-18 sessions reconciling overlap.
- **Two STOP-ASKs surfaced architectural questions that should have been sprint-kick-off-pre-decided.** Decision H (Day 18 — no client-side PII caching) and Decision K (Day 19 — Server Components vs client hydration for Trust Center) both arose mid-implementation. Either would have been a 30-minute pre-flight decision at sprint kick-off; instead each consumed ~2 hours mid-day with code already partly written. Sprint 3 kick-off must include "what are the architectural questions I expect to surface mid-sprint, and can I pre-answer them now?"
- **Day 20 EPS-credentials incident.** Production credentials sent in plaintext chat (user-initiated, but the agent didn't immediately direct user to a private channel for credential transfer); auto-mode classifier blocked the Secrets Manager write; ~45 minutes of session context consumed on the resolution loop. Better path: surface the workaround command BEFORE attempting the agent-side write the first time, then run it in 5 minutes once the user confirms.

### What gotcha caught us most

- **Postgres CHECK constraint auto-naming convention.** Day 15 migration 0006 ran `ALTER TABLE tenants DROP CONSTRAINT tenants_type_check` (the Postgres-auto-generated name) — but the original migration 0001 used Drizzle's inline `check()` which generated `tenants_type_chk` (Drizzle convention). Constraint name mismatch caused the migration to fail in CI on first push. Documented in `gotchas.md`; carried as v2.4 playbook bump candidate (§9.2 reference).
- **`ALTER DEFAULT PRIVILEGES` over-grants UPDATE/DELETE on new append-only tables.** Day 14 audit_logs migration would have silently allowed application-context UPDATEs through `eventpulse_app` despite the no-UPDATE-policy gate (RLS without an UPDATE policy returns "no rows affected" silently, not "permission denied"). Required explicit `REVOKE UPDATE, DELETE, TRUNCATE FROM eventpulse_app` — codified in §4.2.1.1 in v2.3.
- **§20 document list mismatch on Day 19.** User-provided document list didn't match canonical §20.2. STOP-ASK fired before any seed-script code landed; defer-to-§20 decision saved a rebuild. The "defer to canonical reference" reflex is the right one.

### What single change would have saved the most time

**Front-load the playbook read-through at sprint kick-off.** Day 11 should have started with "read §13 (KYC), §20 (Trust Center), §17 (Infrastructure) in full before scoping any items that touch those sections." Days 11-17's 9 §-section amendments accumulated as drift because the reads happened item-by-item rather than sprint-front-loaded; Day 18 AM had to reconcile all of it in one ~3-hour playbook bump session. A 30-minute front-load at Day 11 would have caught most of the drift before it landed.

Sprint 3 kick-off MUST include this: read §11 (EPS), §14 (fee engine), §17 (infra prep for Sprint 4) end-to-end before scoping Day 21.

Sprint 3 kick-off MUST enumerate exact halt conditions if any of these isn't ready by the day the relevant Item needs them. Sprint 2's STOP-ASK list was reactive (added during the sprint as conditions surfaced); Sprint 3's must be proactive.
