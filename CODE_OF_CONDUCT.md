# Code of Conduct

Event Pulse adopts the **[Contributor Covenant, version 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/)** as the standard for behaviour in this project's spaces — code reviews, issue threads, PR comments, Slack, and any official Event Pulse channel.

The full text is at the link above and at <https://www.contributor-covenant.org/version/2/1/code_of_conduct.txt>. Read it.

## What that means here, in plain terms

- Be respectful in every interaction. Disagree about the work, never about the person.
- Assume good intent and ask for clarification before escalating.
- Credit ideas and effort openly; do not take credit for work that isn't yours.
- Keep tenant data, attendee data, and customer conversations confidential by default.
- Welcome new teammates the way you wish you had been welcomed.

## Scope

Applies to everyone participating in Event Pulse work — Public Pulse Agency employees, engaged contractors, vendors with repo access, and any third-party reviewer.

It applies in public project spaces (GitHub issues, PRs, this repository) and when representing the project externally (conferences, posts, customer meetings).

## Reporting

If you experience or witness behaviour that violates this Code of Conduct, report it confidentially to **`conduct@eventpulse.com.bd`**. Reports are acknowledged within 72 hours, the same SLA as security disclosures.

For situations involving an immediate safety concern, do not wait — contact Moshiur Rahman directly.

The reporter's identity is held in confidence to the extent permitted by Bangladesh law and the needs of the investigation. Retaliation against a good-faith reporter is itself a Code of Conduct violation.

## Enforcement

Project maintainers are responsible for enforcement. The escalation ladder follows the Contributor Covenant 2.1 enforcement guidelines: private conversation, written warning, temporary ban, permanent ban — selected proportionate to the severity and pattern of the conduct.

Decisions are recorded in `.claude/memory/decisions.md` under a `conduct:` prefix (without identifying details of any individual) so the project's standards evolve transparently.
